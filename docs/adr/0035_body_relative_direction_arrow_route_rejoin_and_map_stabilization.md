# ADR-0035: 몸 기준 방향 가이드 화살표, 경로 복귀 방향 안내 및 지도 회전·이동 안정화

## 1. 배경 및 문제 의식 (Context)
2026년 10월 1일 보행 내비게이션 현장 로그(`navigation_flight.log`) 분석 결과:

1. **저시력 방향 가이드 화살표가 고정 그림**: `LowVisionDirectionIndicator`는 TMAP 분기 동작(직진/좌/우)별 고정 아이콘만 표시하여, 사용자가 실제로 어느 쪽을 보고 있든 같은 화살표가 나왔다.
2. **목표 방향이 사용자 위치와 무관**: `calculateTargetBearing()`이 "현재 분기점 → 다음 분기점" 직선 방위각이어서 굽은 길이나 경로 이탈 시 복귀 방향을 알려주지 못했다.
3. **지도 흔들림**: 나침반 1초 변화량 p90 13°, p95 23°, p99 49°. 지도는 4.5° 불감대만으로 나침반을 직접 따라 회전했다.
4. **재탐색 시 지도 깜빡임**: 경로가 바뀌면 WebView HTML 전체를 다시 로드하여 위치·확대·회전이 초기화되었다. 당일 재탐색 1건은 GPS 정확도 24m 상태의 27m 오차로 인한 출발점 보정이었다.

## 2. 결정 사항 (Decisions)

### 2.1 목표 방위각: 현재 위치 → 경로 전방 지점 (look-ahead)
- `RouteProgressEngine.pointAtDistance()`로 "현재 투영 위치 + 25m + 경로 이탈 거리(최대 40m)" 지점을 구하고, 현재 GPS 위치에서 그 지점까지의 방위각을 사용.
- 경로에서 벗어날수록 더 앞쪽 경로 지점을 겨냥하므로 **비스듬히 경로로 복귀하는 방향**을 자연스럽게 가리킨다.
- GPS 흔들림 완화: 원형 지수 평활화(α=0.4). 위치가 아직 없으면 기존 분기점 간 방위각으로 대체.
- 음성 정대 안내("왼쪽으로 N도 몸을 돌려…")도 같은 방위각을 사용해 화살표와 일치.

### 2.2 몸 기준 방향 화살표 (`LowVisionDirectionIndicator`)
- `relativeDirectionDegrees = 목표 방위각 − 융합 헤딩` (−180~180, 양수=오른쪽), 시간상수 0.3초 평활화, 3° 이상 변화 시 갱신.
- 84dp 원 안의 굵은 화살표가 해당 각도로 최단 경로 애니메이션(350ms) 회전, 아래에 "N시 방향" 표시, TalkBack 설명 포함.
- 원 색상: 정면 ±20° 이내 녹색 / 회전 필요 노란색 / 경로 이탈 주황색("경로 복귀" 표시).

### 2.3 지도 회전·이동 안정화
- 지도 회전 전용 헤딩 `mapHeadingDegrees`: 시간상수 0.8초 저역 통과, 5° 이상 변화 시 최대 0.3초에 1회 반영. JS 불감대 6°, CSS 회전 전환 0.8초.
- 경로 위(이탈 거리 ≤ 15m)에서는 내 위치 마커를 경로선에 맞춰 표시(map-matching).
- 지도 이동(pan)은 4m 이상 변화 시 0.9초 애니메이션.

### 2.4 재탐색 시 경로 레이어만 교체
- HTML은 최초 경로로 한 번만 생성하고, 경로 변경 시 JS `replaceRoute(coords, crosswalks)`로 경로선·마커 레이어만 교체(위치·확대·회전 유지).
- 출발점 보정 재탐색은 GPS 정확도 ≤ 15m일 때만 수행.

## 3. 검증 결과 (Verification)
- 단위 테스트 `DirectionGuidanceStabilityTest`: 경로 이탈 시 복귀 방위각(북서), 몸 회전 추종(9시), 나침반 ±20° 진동 시 지도 헤딩 90°±8° 유지, map-matching.
