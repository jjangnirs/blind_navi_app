# ADR-0034: YOLO 신호등 위치 검출(Tier 1) 실연결, 모델·색 분석 교차 융합 및 횡단 보조 음성/화면 단일 상태 동기화

## 1. 배경 및 문제 의식 (Context)
2026년 9월 28일~10월 1일 현장 테스트와 비행 기록(`perception_flight.log`) 분석 결과:

1. **팀원 YOLO 모델이 실행되지 않음**: `ped_signal_v1.tflite`가 80바이트 스텁에서 실제 학습 모델(Ultralytics YOLOv8, 입력 `[1,3,640,640]` NCHW, 출력 `[1,6,8400]`, 클래스 `0=pedestrian_green, 1=pedestrian_red`)로 교체되었으나, 앱의 `LiteRtPedestrianSignalEstimator`는 SSD 형식(`[1,320,320,3]`, 4출력)을 가정하고 기본 실행기가 `DeterministicTestModelRunner`(가짜)여서 추론이 한 번도 실행되지 않았다.
2. **시간 검증기 이중 기록**: `TwoTierHybridSignalEstimator`가 `estimateWithinRoi()` 내부에서 이미 검증된 결과를 `LocalVlmSignalVerifier`에 한 번 더 넣어, 프레임당 이력이 2회 기록되었다. 녹색 프레임 뒤에 "UNKNOWN(대기 중)"이 섞여 60% 녹색 합의에 거의 도달하지 못했다 (9/28 로그: 적색 확정 84프레임 / 녹색 확정 1프레임).
3. **원거리 녹색 픽토그램 분절**: 10/01 녹색 30초 구간에서 YOLO는 녹색을 초당 5~8회 안정 검출했으나, HSV 블롭 필터가 잘게 쪼개진 보행 인형 LED를 모두 기각(`G=0/9~21 all blobs filtered`)하여 녹색 확정이 21%에 그쳤다.
4. **모델 미검출 프레임의 뷰파인더 폴백 오판**: 모델이 1~2프레임 놓치면 뷰파인더 전체 HSV 분석으로 넘어가 상단 차량 적색등을 잡아, 보행 녹색 중 "적색" 판정과 이력 오염이 발생했다.
5. **음성/화면 불일치**: 박스·테두리 색은 프레임 원시 색, 배지는 판정 상태, 음성은 판정 변화마다 즉시 발화하여 적색/UNKNOWN이 1초 간격으로 번갈아 나올 때 서로 어긋났다.

## 2. 결정 사항 (Decisions)

### 2.1 YOLO 모델을 Tier 1 위치 제안기로 실연결 (`YoloPedestrianSignalDetector`)
- `org.tensorflow.lite.Interpreter`로 직접 추론, RGBA 프레임 → 114 회색 letterbox → NCHW RGB 0~1 입력.
- 클래스 순서는 모델 파일 끝에 ZIP으로 덧붙은 Ultralytics `metadata.json`의 `names`에서 읽으며, 녹색/적색 클래스를 식별할 수 없으면 모델을 비활성화한다(색 매핑을 추측하지 않음).
- 출력 좌표 정규화 여부 자동 판별, 클래스 무관 NMS(IoU 0.45), 신뢰도 0.25 이상만 후보.
- int8 양자화로 클래스 점수가 0.50에서 포화함을 실측(최댓값 0.50)하여, 모델 단독 적색 인정 기준을 0.30으로 설정.
- 단독 신뢰도가 낮으므로(실사진 시험 0.38~0.43) 색 판정의 최종 근거가 아닌 **위치 제안** 용도로 사용.

### 2.2 모델 분류 × HSV 색 분석 교차 융합 (보수적 비대칭 규칙)
| 모델 | HSV/OpenCV | 결과 |
|---|---|---|
| 녹색 | 녹색 | 녹색 |
| 녹색 | 미검출 + 모델 박스 내 원시 녹색 화소 ≥ 6, 적색 화소 ≤ 녹색/3 | 녹색 |
| 녹색 | 적색 | 적색 (적색 우선) |
| 녹색 | 미검출 | UNKNOWN |
| 적색 | 적색 | 적색 |
| 적색 | 녹색 | UNKNOWN (충돌) |
| 적색(≥0.30) | 미검출 | 적색 |

- 모델이 하우징을 확인한 ROI에서는 세로 2구 슬롯 밝기 검사(ADR-0032)를 생략한다(`housingConfirmed`).
- 여러 신호등 후보는 직전 타깃과의 위치 유사도(중심 거리 + IoU)로 Lock-on 추종(팀원 `LockOnSignalAssociator` 방식 이식).

### 2.3 모델 미검출 1.5초 홀드
- 모델이 마지막으로 검출한 지 1.5초 이내면 뷰파인더 전체가 아닌 **직전 신호등 위치만** 계속 분석한다. 1.5초 초과 시에만 뷰파인더 폴백.

### 2.4 시간 검증기 정비 (`LocalVlmSignalVerifier`)
- 프레임당 정확히 1회만 검증(이중 기록 제거).
- 모든 기각 사유(`REJECTED_*`)를 비행 기록에 남김.
- 박스 한 변이 0.04 미만인 원거리 소형 램프는 접근 차량 급팽창 검사에서 제외(실측: 동일 신호등 면적 9.5px~193px 변동).

### 2.5 횡단 보조 음성·화면 단일 확정 상태 (`CrossingAssistViewModel`)
- 배지, 박스 색, 상태 문구, 음성이 모두 하나의 **확정 상태**를 따른다.
- 히스테리시스: 녹색 5프레임 연속, 적색 2프레임, 확정된 적색/녹색에서 UNKNOWN 전환은 6프레임.
- `GREEN_CANDIDATE`는 내부 상태이므로(SR-F-062) 사용자에게는 UNKNOWN으로만 노출.
- 음성은 확정 상태 변경 시 1회, 화면 문구와 동일 문장으로 발화.
- 녹색 안내 문구: *"녹색 신호로 추정됩니다. 좌우를 살피며 횡단하세요. 앱만으로 안전을 보장할 수 없습니다."* (명령형 "건너가세요" 제거, 추정·한계 고지 포함)
- 영상 분석은 `Dispatchers.Default`에서 실행하고 이전 프레임 처리 중 들어온 프레임은 건너뛴다(코루틴 누적 방지).

## 3. 검증 결과 (Verification)
- 10/01 녹색 구간 로그 재생: 모델 녹색 프레임 137개 중 녹색 융합 21% → 약 87%(추정, 로그의 블롭 개수로 화소 수 대체). 같은 로그에서 YOLO는 실제 녹색 구간 밖에서 녹색을 보고하지 않음.
- 실기기 YOLO 추론 평균 142ms(최대 290ms, 약 6fps, CPU 4스레드).
- 단위 테스트: `YoloHybridFusionTest`, `SignalAnnouncementSyncTest` 추가.
- APK: `app-debug-1001-v35.apk`(모델 연결), `app-debug-1001-v36.apk`(융합·동기화). 현장 재검증 필요.

## 4. 남은 과제
- GPU/NNAPI 가속으로 추론 시간 단축.
- 모델은 Ultralytics(AGPL-3.0) 기반 → 배포 전 라이선스 검토.
- 실제 보행신호 데이터로 재학습해 모델 단독 신뢰도 향상.
